# ForgeFin 统一设计规范

> 本文件是 ForgeFin 界面的**单一事实源**。任何新页面、原型或组件改造，先读本文件，再读同目录 `tokens.css`。
> 生产代码中的 token 事实源是 `src/forgefin-theme/styles/app.css`；本文件与 `tokens.css` 必须与之保持一致，**出现冲突时以 `app.css` 为准并同步修订本文**。

---

## 1. 定位与基调

| 项目 | 说明 |
|---|---|
| 产品 | ForgeFin · 财务管理工具（桌面端优先，窗口最小 1280×800） |
| 用户 | 会计、财务经理、审计、CFO |
| 气质 | 克制、专业、高信息密度；一屏解决一个业务动作 |
| 风格家族 | 企业级数据密集工具（Ant Design 取向），无营销装饰、无大圆角、无渐变堆叠 |
| 语言 | 简体中文界面；数字与代码标识用等宽字体 |
| 反例 | 落地页、宣传页、作品集风格、卡片瀑布流、超大留白、彩色渐变主视觉 |

三条不可协商的原则：

1. **信息密度优先**：能用表格说明的不用卡片，能在行内展示的不用弹窗。
2. **原始数据只读**：银行流水、订单流水、店面收款原始记录不提供编辑/删除入口，只提供查看、确认、审核、作废（有审计留痕）。
3. **金额可信**：任何金额都右对齐、等宽、两位小数、千分位；计算逻辑在后端 `decimal`，前端只负责格式化。

### 2.2 深色（`html.dark`）

深色只做 **token 覆盖**，不动任何组件类：底 `#141414`、面 `#1f1f1f`、次级面 `#181818`、悬停 `#262626`、边框 `#313131`、主文字 `#f5f5f5`、次文字 `#d1d5db`、弱文字 `#9ca3af`、主色仍为 `#1677ff`，状态色改为可读变体（成功 `#49aa19`、警告 `#fa8c16`、危险 `#ff4d4f`），状态浅底统一改为 `rgba(..., .15)`。

**验收线**：删除所有 `html.dark` 之外的硬编码色值后，深浅两套主题下页面不得出现「浅底白字」「深底黑字」或看不清的状态标签。

### 2.3 使用纪律

- 品牌主色只用于：主按钮、当前导航项、链接、选中态、焦点环、关键 KPI 数字。
- 状态色只表达状态，不能当装饰：绿=正常/通过，橙=待处理/警告，红=不平/失败/危险操作，蓝=已过账/进行中。
- 表格里状态一律用胶囊 badge（浅底 + 同色文字 + 可选圆点），不用整列纯色文字。

## 3. 字体与数字

| 用途 | 规格 |
|---|---|
| 正文字族 | `Inter` → `PingFang SC` → `Microsoft YaHei` → `system-ui` |
| 等宽 | `ui-monospace, "SF Mono", Menlo, Consolas, monospace`（单号、账号、金额、原始 JSON） |
| 页面标题 | 16px / 600 |
| 区块标题 | 14px / 600 |
| 表格正文 | 12.5–13px / 400（行高 30px） |
| 表头 | 13px / 500，`--color-secondary`，sticky |
| 辅助文字、时间戳 | 12px / 400，`--color-tertiary` |
| KPI 数值 | 23–26px / 600，`text-num` |

数字规则（全局强制）：

- 金额：两位小数 + 千分位，如 `11,970.00`；负数用 `-1,200.00` 并加 `text-danger`。
- 百分比：一位小数，如 `0.25%`。
- 等宽 + 右对齐：金额列加 `.text-money`，数量/单号列加 `.text-num`。
- 日期 `YYYY-MM-DD`；时间 `YYYY-MM-DD HH:mm:ss`；导出/RFC3339 场景另行标注。
- 金额单位只在表头或列标签声明一次（如「金额（元）」），单元格内不重复货币符号。

## 4. 间距、圆角、阴影、尺寸

- 间距走 4px 基准：`4 / 8 / 12 / 16 / 20 / 24 / 32`。
- 圆角：`--radius-xs 2` / `sm 4`（tag、chip）/ `md 6`（按钮、输入）/ `lg 8`（卡片、表格容器）/ `xl 12`（抽屉、弹窗）。
- 阴影克制：卡片 `--shadow-sm`，抽屉/弹窗 `--shadow-lg`，行 hover 不加阴影。
- 布局尺寸：侧栏 `220px`（折叠 64px）、顶栏 `64px`、表格行高 **30px**（表头 32px，紧凑 28px）、详情抽屉 `480px`。
- 内容区最大宽度不限制，但表格容器左右内边距固定 20px。

## 5. 页面骨架与导航

### 5.1 三段式骨架

```
┌ sidebar 220 ┐┌ header 64 ─────────────────────────────┐
│ brand       ││ 面包屑：原始凭证 / 银行流水    [页面动作] │
│ nav groups  │├─────────────────────────────────────────┤
│             ││ toolbar：筛选 / 搜索 / 批量动作           │
│             ││ KPI 或校验条（可选）                     │
│             ││ 主表格（sticky 表头，内部滚动）           │
│ nav-foot    │├─────────────────────────────────────────┤
│             ││ 页脚：选中区域统计（合计/平均/数量…）｜分页 │
└─────────────┘└─────────────────────────────────────────┘
```

- 侧栏深色 `--color-sidebar`，当前项左侧 2px 品牌色高亮 + `--color-brand-soft` 底（深色下用 `rgba` 版本）。
- 顶栏：左面包屑（分组名 12.5px 弱化 + 分隔 `/` + 模块名 16px 强调），右侧只放**页面级**动作；刷新按钮只显示图标，`title`/`aria-label` 写「刷新」。
- 主表格：`sticky` 表头、末行去边框、斑马行用 `--color-surface-alt`、选中行 `--color-surface-active`。
- **页脚（强制）**：固定在内容区底部，一行 40px，高 `--color-surface` 底 + 上边框。左侧是 **Excel 式选中区域统计**，右侧是记录数与分页。页脚不是装饰条，任何带主表的页面都必须有。

### 5.2 导航结构（与 `src/nav.rs` 一致）

首页 ｜ 总账（凭证管理、凭证录入、凭证审核、凭证查询、会计科目、客户/供应商、科目余额、明细账、总账、试算平衡表）｜ 报表中心 ｜ 应收管理 ｜ 应付管理 ｜ 固定资产 ｜ 出纳管理 ｜ 预算管理 ｜ 税务管理 ｜ **原始凭证**（导入中心、对账中心、审计日志、银行流水、订单流水、店面收款、聊天记录、数据汇总）｜ 账套管理 ｜ 系统设置。

- 原型必须复用同一侧栏结构与分组顺序，只改变高亮项；不允许自创分组或改图标语义。
- 本规范新增的两项为 **店面收款**（`/raw-data/store-collection`）与既有 **导入中心**（`/raw-data/import`）。

## 8. 五大页面规格

共同约束：原始表只读；金额等宽右对齐；列表默认按时间倒序；每次导入/审核/生成写入审计日志；示例数据脱敏（账号 `1001****7575`、姓名 `张*`、手机 `138****1234`、公司 `示例商贸有限公司`）。

**每一页都必须有可用的页脚统计**（参见 §6「页脚统计」）：主表支持单元格点击 / 拖拽框选 / `Shift` 扩选，页脚实时输出选中区域各数值列的合计、平均、数量、最大、最小，文本列输出非空计数，并提供「清除」与全选（`Ctrl/⌘+A`）。

### 8.1 导入中心（F1）

- **目标**：把银行流水、订单流水、店面收款等原始文件安全落库，且导入结果可核对、可回滚感知。
- **骨架**：Stepper（选择文件 → 列映射 → 校验 → 结果）+ 批次历史表 + 右侧文件详情。
- **区域**：
  1. 上传区：拖拽或浏览；支持「扫描原始数据目录」（免逐份选择）；文件类型徽标（TSV / CSV / XLSX）。
  2. 列映射预览：原始表头与样本行双列对照，人工可改字段识别；关键列不完整时红字提示但**不阻断导入**。
  3. 余额连续性校验：`Σ(转入 − 转出)` 与相邻批次衔接检查，展示不连续位置与差额；警告级别为橙色，仅提示不阻断。
  4. 入库结果：成功写入行数 / 失败行数与错误明细（行号 + 原因 + 原始行），提供「前往银行流水」跳转。
- **批次历史表列**：批次号、来源类型、文件名、总行数、成功、失败、导入时间、操作（查看 / 前往流水）。
- **交互**：重复批次号拒绝导入并提示已存在批次；导入中显示扫描/写入进度；批次历史全部展示不分页。

### 8.2 银行流水（F2）

- **目标**：核对银行侧原始流水与余额，确认后作为对账与凭证生成依据。
- **区域**：工具栏（关键字、交易日期区间、批次、校验状态筛选）+ 余额校验条（三色汇总，绿正常/红不平/灰待确认）+ 主表 + 行详情抽屉（480px）。
- **主表列**：交易日期、交易时间、业务单号、对方单位、对方账号（脱敏）、摘要/用途、金额（右对齐，收入绿/支出常规）、余额、校验状态、来源批次、操作。
- **行详情**：核心字段、余额衔接上下文（上一笔余额 → 本笔 → 下一笔）、关联凭证、原始 JSON 摘要（等宽、可折叠）。
- **交互**：点击行选中并打开抽屉；「确认余额」按批次二次确认，确认范围（批次 + 条数 + 差额）必须展示；不可编辑、不可删除。
- **空态**：暂无数据时引导「前往导入中心」。

### 8.3 订单流水（F3）

- **目标**：校验订单金额、手续费与商户实收，暴露费率与实收差异。
- **区域**：工具栏（关键字、交易时间、支付方式、仅看费率差异、会计期间）+ 合计条（订单金额合计 / 手续费合计 / 商户实收合计）+ 主表 + 行详情抽屉。
- **主表列**：交易时间、第三方订单号、工行订单号、支付方式、交易金额、手续费、商户实收、费率检查、归集状态、关联凭证。
- **行详情**：费率复算（交易金额 × 费率 = 应收手续费，与原始手续费对比，差异高亮）、结算日期与 T+1 收入归属、数据汇总归集关系。
- **交互**：费率差异行整行淡黄、实收差异行整行淡红；手动调整手续费仅影响本地复算视图，不改原始值；明细一次性完整展示。

### 8.4 店面收款（F9）

- **目标**：登记店面线下收款（现金、个人码、对公转账通道），审核后归集进数据汇总，形成凭证来源。
- **区域**：左侧待处理队列（草稿/待审核）+ 右侧收款详情抽屉；顶部按收款方式合计（现金 / 个人码 / 对公转账）与对账合计、差异。
- **列表列**：收款日期、收据号、客户姓名、客户电话（脱敏）、收款方式、收款金额、到账账户、事由/备注、附件数、状态、操作。
- **详情**：基础信息（收款日期、收据号、客户）、收款信息（方式、金额、到账账户、事由）、单据照片附件（缩略图网格，可预览/删除）、操作记录（谁在何时做了什么）。
- **动作**：保存草稿 / 保存并提交 / 审核通过 / 作废（作废需二次确认 + 原因，行内删除线保留）；审核后「生成汇总」跳转数据汇总。
- **校验**：金额必须 > 0 且两位小数；到账账户必填；对公转账通道必须选择账户；附件支持 jpg/png/pdf，单文件 ≤ 10MB。

### 8.5 对账中心（F4）

- **目标**：按日期把订单流水、银行流水、数据汇总三方勾稽，输出差异清单并驱动审核与凭证生成。
- **区域**：日期/期间选择 + 「开始对账」+ KPI（流水总额、实收合计、已匹配合计、差异合计）+ 差异表 + 三方勾稽视图。
- **KPI**：POS 实收合计、已匹配合计、差异待处理金额/条数、已忽略条数。
- **差异表列**：日期、单号、差异字段（实收 / 手续费 / 收入）、账面值、实收值、差异金额（红）、差异原因、状态、操作（定位原行 / 忽略差异 / 生成汇总草稿）。
- **交互**：点击差异行定位到对应原始行；「忽略差异」需二次确认 + 原因；对账前提示将影响的日期范围；对账结果可导出 Excel；无数据时按缺失来源分别给空态（无订单数据 / 无银行数据 / 无汇总记录）。

## 9. 硬性业务约束（设计层必须体现）

1. 原始流水只读——页面不出现编辑、删除入口。
2. 破坏性/状态变更操作必须二次确认，并记录操作人、时间、原因。
3. 批次历史、导入错误明细、对账差异一次性完整展示；主流水列表 50 行/页分页。
4. 错误文案中文且可执行，包含具体数字，如「借贷不平：借 12,000.00 ≠ 贷 11,970.00」。
5. 金额全链路 `decimal`，前端仅格式化，禁止浮点运算展示。
6. 示例数据脱敏，不得出现真实公司、人名、完整账号。
7. 每个页面的主操作不超过 1 个；次级动作收敛进工具栏或行内「更多」。
8. **页脚统计必须真实可用**：选中区域的数值列要输出合计、平均、数量、最大、最小；文本列输出非空计数；数字格式化遵循第 3 节。
